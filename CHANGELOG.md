# CHANGELOG — Basalt Perfume

История изменений составлена по двум предоставленным архивам: GitHub-резервной копии от `2026-10-20` и более позднему локальному архиву, подготовленному к публикации. Даты отдельных промежуточных релизов в исходниках указаны не везде, поэтому там, где точная дата не подтверждена, я фиксирую версию или последовательность изменений без выдуманной даты.

## 2026-10-20 — GitHub backup

Зафиксированное состояние проекта до последующей переработки структуры репозитория:

- Проект был представлен тремя отдельными каталогами: Telegram Bot, HTML WebApp и PHP WebApp.
- Telegram Bot содержал runtime-код, обработчики, сервисы, слой базы данных, тесты и CLI-инструменты.
- Бот принимал Excel/CSV прайс-листы, обрабатывал их, собирал каталог парфюмерии и обслуживал подписки, роли и уведомления.
- WebApp поставлялся в двух вариантах оболочки — HTML и PHP — с серверной частью на PHP и общей базой MySQL.
- В приложении уже присутствовали каталог, поиск, сравнение цен, избранное, управление подпиской, локализации RU/EN/KZ и административные функции.

## После 2026-10-20 — переработка структуры проекта

### Репозиторий и разделение ответственности

- Структура GitHub подготовлена к разделению на четыре ветки: `main`, `bot`, `sql` и `web`.
- `main` выделена под общую документацию проекта и Admin CLI.
- `bot` сведена к материалам настройки профиля и запуска Mini App через BotFather: локализованным текстам, логотипу и изображению описания.
- SQL bot- и web-частей собраны в отдельную ветку `sql`: сохранены исходные SQL-файлы и подготовлена единая рекомендуемая последовательность миграций.
- Основная логика приложения сосредоточена в `web`. Постоянный Telegram bot runtime не является обязательной частью текущей web-архитектуры.

### Web: браузерная авторизация и разделение режимов

- Для обычного браузера подготовлен Telegram OpenID Connect Authorization Code Flow с PKCE.
- Обмен authorization code вынесен в Cloudflare Worker relay; `Client Secret` хранится в секретах Worker, а PHP выполняет проверку ID token.
- В browser/Desktop-режиме введены чистые маршруты для разделов приложения; сохранены отдельные URL Mini App.
- В архитектуре v13 разделены `mobile/` и `desktop/` оболочки. Telegram WebApp, мобильный браузер и desktop-браузер используют общий API и общую БД, но получают соответствующий интерфейс.
- В desktop-режиме развита боковая навигация, ограничение ширины контента, breadcrumb, отдельная компоновка административных блоков и центрированные диалоги.

### Web v13.3 — обработка загрузок на сайте

- Добавлен отдельный сценарий загрузки прайс-листов непосредственно через web-приложение.
- Загруженные файлы размещаются в приватном файловом хранилище вне DocumentRoot.
- Для web-загрузок используется отдельная очередь `web\_upload\_site\_jobs`.
- Обработка передана отдельному Python Worker, запускаемому через Cron и использующему приватный парсер.
- Скачивание выполняется веб-приложением напрямую; передача файлов через Telegram-бота не требуется.

### Web v13.4 — устойчивость очереди и диагностика

- Для задач загрузки расширена диагностика статусов, количества попыток и ошибок обработки.
- Worker получил heartbeat для длительных задач и восстановление зависших блокировок.
- Предусмотрена обработка повторных аварийных запусков, чтобы задачи не оставались бесконечно в состоянии `processing`.
- Оптимизирован polling статуса загрузок; разделены front controller API и внутренние обработчики.
- Исправлены отдельные элементы интерфейса и взаимодействия в desktop/mobile: FAQ, подтверждение удаления файла, уведомления, списки админ-панели и элементы управления.

### Web v13.5 — уведомления и интерфейс

- Добавлено групповое уведомление о принятии загруженных файлов.
- Обновлены индикатор непрочитанных уведомлений и действие «Прочитать все».
- Выполнены исправления отдельных desktop/mobile-компонентов, диалогов, настроек темы и состояния загрузки.
- Для указанного пакета исправлений SQL-миграции и обновление Python Worker не требовались.

### Web v13.10.20 — режимы браузера

- Явно выделены три режима: `telegram-webapp`, `mobile-browser` и `desktop-browser`.
- Для Telegram WebApp сохранены HTML URL.
- Обычный мобильный браузер направляется на `/m/...`.
- Desktop-браузер использует PHP-страницы и чистые маршруты.
- Стабильной точкой входа API остаётся `public\_html/api.php`; внутренние файлы `api/` не предназначены для прямого HTTP-доступа.

## Локальный архив — подготовка к публикации в четырёх ветках

### `main` — Admin CLI

- Подготовлен самостоятельный Admin CLI с меткой версии `13.10.32-cli.1`.
- Поддержаны просмотр состояния и статистики БД, таблиц, пользователей, избранного, подписок, ключей, прайс-листов, ошибок и очередей.
- Добавлены операции назначения ролей, блокировки и разблокировки пользователей, управления ключами, подписками и настройками приложения.
- Для опасных действий предусмотрены подтверждения и проверки защищённых администраторских профилей.
- Добавлена команда `migrate-db` с предварительной проверкой совместимости, JSON-отчётом и отдельным явным подтверждением целевой БД для записи.
- Добавлена очистка Python cache-каталогов.

### `bot` — материалы BotFather

- В актуальный состав ветки включены тексты профиля RU/EN/KZ.
- Добавлены логотип и изображение описания.
- Ветка не содержит постоянно работающий bot runtime. Её назначение — оформление бота и настройка точки запуска WebApp через BotFather.

### `sql` — объединённый пакет схемы данных

- Собрана упорядоченная цепочка из 14 миграций `001`–`014`.
- Сохранены исходные SQL-материалы bot- и web-частей, включая миграции, диагностические запросы, legacy-файлы и seeds.
- Подготовлены два полных установочных дампа:
    - `Basalt\_Perfume\_FULL\_INSTALL\_EMPTY\_BRANDS.sql`;
    - `Basalt\_Perfume\_FULL\_INSTALL\_WITH\_BRANDS.sql`.
- В полные дампы сведены базовая схема и необходимые web-таблицы очередей загрузок и настроек browser access.
- Документированы разные сценарии: импорт одного полного дампа в новую пустую БД и применение только отсутствующих миграций к существующей БД.

### `web` — основная составляющая проекта

- Объединены мобильная HTML-оболочка, desktop PHP-оболочка, общий PHP API и общая бизнес-логика.
- Включены приватный Python Worker и парсер для обработки web-загрузок.
- Включены материалы по обнаружению конфликтующих загрузок и справочные файлы парсера/брендов.
- Добавлены `SETUP.md`, `API.md` и шаблон инвентаризации production-хоста.
- Добавлены Docker-конфигурация, Makefile, pytest, pre-commit и GitHub Actions CI.
- В CI предусмотрены проверки PHP, JavaScript, Python, тесты и сканирование секретов.
- Описан отдельный Cloudflare Worker для Telegram OIDC relay.

## Примечания к версиям и совместимости

- Admin CLI в локальном архиве имеет собственную метку `13.10.32-cli.1`.
- `public\_html/README.md` web-ветки сохраняет заголовок `v13.10.20`, а README Admin CLI указывает совместимость с WebApp `v13.10.32`. Эти метки не следует считать единым подтверждённым номером релиза без дополнительной сверки версий в исходниках.
- SQL-проверки и CI не заменяют тестирование на production-хостинге. Полные SQL-дампы в документации предназначены для новой пустой БД; перед изменением существующей БД необходима резервная копия и сверка уже применённых миграций.
- Незавершённые задачи и визуальные пожелания не включаются в этот журнал как выполненные изменения.
