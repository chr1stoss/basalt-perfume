# Basalt Perfume — единый пакет SQL-миграций и полных дампов

## Что внутри

- `01_ORDERED_MIGRATIONS/` — рекомендуемая последовательность из 13 уникальных инкрементальных миграций для существующей БД.
- `02_ORIGINAL_SQL/BOT/` — все SQL из bot-архива, включая исходные миграции, старые/актуальные дампы, диагностические SQL и seed-файлы. Структура подпапок сохранена.
- `02_ORIGINAL_SQL/WEB/` — все 9 SQL-файлов из web-архива и отдельно сохранённый standalone SQL.
- `03_FULL_INSTALL_DUMPS/` — два полных дампа для создания новой пустой БД: без заполнения справочника брендов и с брендами/алиасами. Оба объединяют актуальную схему bot-версии и обе веб-очереди (`web_upload_jobs`, `web_upload_site_jobs`) с настройками web-доступа.
- `04_REFERENCE/` — README миграций bot-версии.

## Важно: новая БД или существующая БД

### Новая пустая БД

Выбрать в phpMyAdmin одну из двух файлов в `03_FULL_INSTALL_DUMPS/` и импортировать **только один**:

- `Basalt_Perfume_FULL_INSTALL_WITH_BRANDS.sql` — схема + справочник брендов и алиасов.
- `Basalt_Perfume_FULL_INSTALL_EMPTY_BRANDS.sql` — схема с пустыми таблицами брендов и алиасов.

Дампы предназначены только для чистой новой БД. Они содержат `DROP TABLE IF EXISTS` и удалят одноимённые таблицы и данные при импорте. Не импортировать поверх рабочей production-БД. Дамп не создаёт саму базу данных — сначала создать пустую БД и выбрать её.

### Существующая БД

Сделать резервную копию, проверить текущую структуру и выполнить **только отсутствующие** миграции из `01_ORDERED_MIGRATIONS/` по номеру, от 001 до 013. Не запускать вслепую всю цепочку: некоторые ранние изменения могли быть применены ранее через bot- или web-версию.

Эта последовательность предполагает, что базовые таблицы приложения уже существуют (`users`, `user_settings`, `subscription_keys`, `products`, `admins`, `price_lists`, `app_settings`). Если какая-либо базовая таблица отсутствует, остановиться и сверить схему с исходной установкой; миграции не заменяют базовый дамп.

## Дубликаты и перекрытия между исходниками

Чтобы не применять одно изменение дважды, в рекомендуемую цепочку включена одна каноническая копия каждого изменения:

| В web-архиве | Эквивалент в bot-архиве / решение |
|---|---|
| `000_allow_none_role.sql` + `001_user_favorites.sql` | Объединены в bot `08_none_role_favorites.sql`; в цепочке один файл `006`. |
| `002_telegram_notification_queue.sql` | Bot `09_telegram_notification_queue.sql`; в цепочке один файл `007`. |
| `003_display_product_dimensions.sql` | Bot `10_display_product_dimensions.sql`; в цепочке один файл `008`. |
| `004_role_activation_keys.sql` | Bot `11_role_activation_keys.sql`; в цепочке один файл `009`. |
| `006_admin_user_deletion_queue.sql` | Bot `12_admin_user_deletion_queue.sql`; в цепочке один файл `011`. |
| `005_seller_privacy_settings.sql` | В bot-дампе 14/15 эти поля уже присутствуют; для существующей БД оставлена отдельная web-миграция `010`. |
| `007_browser_access_and_web_uploads.sql` | Только web-часть; `012`. Отдельный `basalt-perfume-db-migration.sql` — точная копия этого файла. |
| `008_website_upload_queue.sql` | Только web-часть; `013`. |

В bot-архиве `01_upgrade_existing_language.sql` и `02_upgrade_existing_webapp.sql` — одинаковые по назначению миграции; в рекомендуемой цепочке использована одна копия (`001`). Bot `07_consolidated_upgrade_roles_buyer_price_boost.sql` объединяет несколько более ранних изменений (язык, cleanup, ciphertext, меню, роли/множители и favorites). Он сохранён в `02_ORIGINAL_SQL/BOT/migrations/`, но **не запускается вместе с рекомендуемой цепочкой**, иначе будут повторяться изменения.

Старые bot-дампы `01/02` и legacy-дампы также сохранены в исходниках для истории, но для новой установки предпочтительны `14/15`, дополненные web-таблицами.

## Содержимое полного дампа

В основу взяты актуальные bot-дампы `14_full_install_empty_brands.sql` и `15_full_install_with_brands.sql`. В них уже сведены базовые таблицы и миграции bot-версии: роли, множители, ключи, настройки языка/меню/приватности, избранное, уведомления, размеры DISPLAY, очереди уведомлений и удаления пользователей. В оба итоговых файла дополнительно включены таблицы `web_upload_jobs` и `web_upload_site_jobs` и настройки `browser_access_enabled`, `web_price_upload_enabled` из web-миграций.

Дамп не содержит production-пользователей, реальных ключей активации, прайс-листов или клиентских записей. Это чистая схема; бренды/алиасы есть только в варианте `WITH_BRANDS`.

## Проверки и ограничения

- Исходные SQL-файлы сохранены без изменения в `02_ORIGINAL_SQL/`.
- В `01_ORDERED_MIGRATIONS/` дубли исключены и пронумерованы в порядке применения.
- Полные дампы — объединённые установочные файлы; их нельзя применять к существующей БД.
- Перед production-миграциями обязательно сделать backup и сравнить структуру.
- Файлы не исполнялись на реальном MySQL/Percona сервере; проверена структура и согласованность содержимого, но не фактический импорт на хостинге.
